# 馆际护理规程

检查发现按规程决定是否附加复检，实际发生处置才重置相应阶段时限。静置下限从处置完成时刻起算，复检不得早于下限或晚于表中上限。缺少现场回执时阶段保持待确认。经确认已经超过安全上限的对象优先占用合格班组，紧急对象的转馆须由原馆与接收馆共同确认。

## 可执行参数

`careflow/model.py` 中的 `Protocol` 默认值与本节一致；`protocol.csv` 可覆盖。

| 参数 | 默认 | 含义 |
|---|---|---|
| `quiet_min_days` | 4 | 静置下限：复检最早日期 = 处置完成日 + 该值 |
| `recheck_max_days` | 6 | 复检上限：复检最晚日期 = 处置完成日 + 该值 |
| `recheck_urgency_days` | 2 | 距复检上限不足该天数时判为“窗口紧迫” |
| `deadline_urgency_days` | 2 | 距有效截止不足该天数时判为“截止临近” |
| `horizon_days` | 14 | 值班员比较支援方案的窗口 |
| `batch_atomic` | true | 同一批次不拆开处置 |
| `urgent_transfer_dual_confirmation` | true | 紧急转馆须原馆与接收馆共同确认 |

## 判定顺序

1. **合并护理链**：同一 `object` 的多条工序是一件事；交接两侧重复登记的同一工序合并，不新增待交付对象。
2. **先后约束**：前置工序未完成时，后续工序“登记完成”会被判为冲突；已排期的后续工序会提示等待。
3. **检查发现**：
   - `shorten`：以发现日（缺省用事件日）或现有截止为基准收紧时限；
   - `add_recheck`：不改变原截止，只在完整交付上追加复检要求；进度里没有复检工序时补一个“待完成”的复检；
   - `reset`：只有该阶段**实际完成**后才重置；未完成时不给新时限，并记录“暂不重置”。
4. **静置与复检窗口**：
   - 下限 = 处置完成日 + `quiet_min_days`；
   - 上限 = min(处置完成日 + `recheck_max_days`, 检查限制, 仍有效的工序截止)；
   - 若工序行上的复检截止早于静置下限，视为旧计划，按实际处置完成时间重置，不采用旧截止；
   - 下限晚于上限即“不存在合规窗口”；已过上限且未复检即“已确认错过安全窗口”。
5. **证据状态**：缺报、未知、缺回执 → `evidence_gap` 或 `pending_confirmation`，不判逾期；
   只有截止确实已过或窗口确实关闭才算 `confirmed_missed`。
6. **交付口径**：
   - `treatment_complete`：处置工序为 `done`（且回执满足要求）；
   - `full_delivery`：护理链全部 `done`、无证据缺口、无已确认错过；
   - `on_time_delivery`：`full_delivery` 且没有任何步骤晚于有效截止；否则记 `late`。

## 支援规程

- 优先处理“已确认错过”和“窗口紧迫”的对象，避免进一步恶化。
- 已确认错过安全上限的对象占用合格班组时只记为**减损支援**，不计入通过件数。
- 缺证据的对象必须等馆方确认后才能排支援，不占用通过件数名额。
- 在途护理链保持锁定，正式交还（`returned`）后才可重新安排。
- 同一检查、同一批次、同一交接批次的约束优先于总体完成率。
