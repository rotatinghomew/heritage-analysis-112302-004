# 馆际轮护的高风险工序缺口与交接

本地数据与术语材料供业务人员整理分析资料使用，所有记录均为合成样例。

## 输入

`fixtures/` 包含 `primary.csv`, `support-1.csv`。文件首行为字段名，空值表示来源没有给值。记录用于说明输入结构和实体关联，不含统计结论。

`examples/weekly/` 是更完整的样例，额外演示检查发现、场地释放和交接状态。

## 解释

有效范围、证据和审批状态按业务记录本身判断。不同表中的同一标识用于关联记录，不代表两份独立观察。资料存在未知、零和缺报的区别。

## 字段

### primary.csv（必需）

| 字段 | 说明 |
|---|---|
| `object` | 藏品标识；同一藏品的所有工序共用，交接不新建藏品 |
| `site` | 当前登记馆 |
| `step` | `inspect` / `treat` / `recheck` / `return`（接受中文别名） |
| `event` | 事件日期；已完成步骤可另给 `completed_on` 表示实际完成日 |
| `deadline` | 工序截止；会被检查发现和静置规程收紧 |
| `inspection` | 检查号；同一检查号关联多件藏品/多道工序 |
| `elapsed` | 已用天数；`0`、空值、`unknown` 含义不同 |
| `status` | `done` / `in_progress` / `scheduled` / `not_started` / `pending_confirmation`；空值为缺报 |
| `receipt` | 可选。现场回执 `yes/no`；为 `no` 或空时已完成步骤转“待确认” |
| `material` | 可选，用于按材料汇总 |
| `treatment_type` | 可选，用于按处理类型汇总 |
| `batch` | 可选，同一批次不可拆给不同班组 |
| `depends_on` | 可选，逗号分隔的前置步骤；省略时按 inspect→treat→recheck→return 推定 |

### findings.csv（可选）

| 字段 | 说明 |
|---|---|
| `inspection` | 检查号；`object` 为空时作用于所有使用该检查号的藏品 |
| `object` / `step` | 可进一步限定作用对象与工序 |
| `effect` | `shorten`（收紧截止）/ `add_recheck`（只要求附加复检）/ `both` / `reset`（实际完成后重置）/ `extend` |
| `days` | 重置或顺延天数 |
| `limit_days` | 从发现日（或事件日）起算的新上限 |
| `recheck` | 是否要求附加复检 |
| `confirmed` | 发现是否已确认；未确认的发现不影响时限 |
| `finding_date` | 发现日期 |

### support-1.csv / support-*.csv（可选，可多份）

`team, site, skill, start, end, capacity`。`skill` 取 `treat` / `recheck`；`start`/`end` 为闭区间的差旅窗口。

### spaces.csv（可选）

`site, available_from, available_to, capacity, note`。表示馆方已腾出的场地；只有在该窗口内且未超容量才可安排。

### transfers.csv（可选）

`object, from_site, to_site, state, urgent, origin_confirmed, receiving_confirmed, returned_on, note`。

- `state`：`planned` / `in_transit` / `received` / `returned` / `cancelled`
- `in_transit` 与 `received` 期间护理链锁定，不可为优化完成率而改派
- `urgent=true` 的转馆必须 `origin_confirmed` 与 `receiving_confirmed` 同时为 `yes`

### protocol.csv（可选）

覆盖默认规程参数：`quiet_min_days`（静置下限）、`recheck_max_days`（复检上限）、
`recheck_urgency_days`、`deadline_urgency_days`、`horizon_days`、`batch_atomic`、
`urgent_transfer_dual_confirmation`。默认值见 `docs/业务规程.md` 与 `careflow/model.py`。

## 值的语义

| 写法 | 含义 |
|---|---|
| 空 | 来源没有给值（`missing`） |
| `unknown` / `?` | 来源明确表示不知道（`unknown`） |
| `0` | 明确为零（`zero`），例如已用 0 天 |
| 其他 | 有值（`present`） |

这三种情况在评估结果里分别落到不同的证据状态；缺报和未知不会自动等同于逾期或完成。
